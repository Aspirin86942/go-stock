# 股票筹码分布工具设计

## 1. 背景

当前仓库已经具备较完整的单股票分析数据链路，但“筹码分布”仍是明显缺口。

已确认的现状如下：

- 后端已有东方财富 K 线工具，能够获取 `open`、`close`、`high`、`low`、`volume`、`amount`、`amplitude`、`turnoverRate`
- 当前 AI 分析输出中，若缺少筹码分布，往往只能提示“未提供更细的成交额、换手率、筹码分布、股东户数变化”
- 仓库内没有现成的 `GetStockChipDistribution` 或同义工具
- 东方财富网页确实存在“筹码分布”展示，但目前无确切信息证明存在稳定、公开、独立的后端 CYQ 接口可直接调用
- 已检索到东方财富前端公开源码中包含 CYQ 计算逻辑，且输入字段与现有 K 线数据高度匹配

因此，本次目标不是继续为 AI 输出补一段“缺失说明”，而是补上一个真实可调用、可测试、可复用的筹码分布工具。

## 2. 目标

本次改动需要同时满足以下目标：

- 为单股票分析提供真实的“筹码分布”工具，而不是近似占位数据
- 复用现有东方财富 K 线数据链路，不新增脆弱网页抓取依赖
- 默认输出最新一期的摘要指标和价格分布明细表，供 AI 直接分析
- 同时接入两条现有工具调用路径，避免只在部分 agent 场景可用
- 保持结果可测试，至少覆盖算法输出、工具 markdown 输出和多股票顺序

## 3. 非目标

以下内容不在本次范围内：

- 不新增网页私有接口抓取或长期维护反爬逻辑
- 不实现周 K、月 K、分钟 K 的筹码分布版本
- 不把股东户数、资金流、龙虎榜等数据混成“伪筹码分布”
- 不承诺与东方财富网页像素级一致，只要求算法口径一致、输出语义可解释
- 不在本次顺带修改其他 AI 分析提示词或前端展示页面

## 4. 方案对比

### 方案 A：本地移植 CYQ 算法并基于现有 K 线计算（推荐）

使用现有日 K 数据和换手率，在后端本地完成筹码分布计算。

优点：

- 不依赖隐藏接口，稳定性最高
- 输入数据已在仓库中打通，复用成本低
- 计算结果可单元测试，行为更可控
- 后续若发现更稳定的数据源，可保持对外工具契约不变

缺点：

- 首次需要将 CYQ 算法完整移植到 Go
- 需要定义价格桶精度、默认样本天数等参数口径

### 方案 B：继续反查网页私有接口

尝试定位东方财富页面背后可能存在的筹码分布接口，直接拉取结果。

优点：

- 如果存在稳定接口，实现会更短

缺点：

- 目前无确切信息证明存在稳定可调用的独立接口
- 即使暂时能调用，后续也极易因页面变动或风控而失效
- 可测试性差，维护成本高

### 方案 C：使用其他数据近似构造筹码画像

使用股东户数、资金流、换手率等信息拼接出“近似筹码分析”。

优点：

- 实现快

缺点：

- 结果不是真正的筹码分布
- 容易误导 AI 对成本区间和集中度的判断

### 结论

采用方案 A。先在后端本地实现 CYQ 算法，使用现有东财日 K 数据计算筹码分布，并暴露为统一工具。

## 5. 总体设计

本次设计分三层实施：

1. CYQ 纯计算层
2. 后端工具层
3. agent 工具包装层

### 5.1 CYQ 纯计算层

文件建议：

- `backend/data/chip_distribution_calculator.go`

职责：

- 输入 `[]KLineData`
- 完成筹码衰减、当日新增筹码分配、成本统计和分布桶汇总
- 输出结构化结果，供不同工具层复用

设计原则：

- 计算逻辑独立于工具调用框架
- 不直接拼 markdown，不混入 OpenAI/agent 上下文逻辑
- 对异常输入给出明确错误，而不是静默返回空结果

### 5.2 后端工具层

文件建议：

- `backend/data/tool_stock_chip_distribution.go`
- `backend/data/tools.go`

职责：

- 解析工具参数
- 拉取指定股票的东财日 K 数据
- 调用 CYQ 计算器
- 渲染摘要指标和明细表 markdown
- 按现有多股票并行模式输出结果

设计原则：

- 延续现有 `GetEastMoneyKLine` 风格
- 输出字段名尽量直接给 AI 使用，避免二次解释
- 多股票时按输入顺序拼接，不因并行打乱顺序

### 5.3 agent 工具包装层

文件重点：

- `backend/agent/tools/data_tools_wrapper.go`

职责：

- 在另一套 agent tool registry 中暴露同名工具
- 保持参数和返回语义与后端工具层一致

设计原则：

- 两条调用链的工具名、参数、默认值保持一致
- 不在 wrapper 内复制核心算法，只调用共享数据层能力

## 6. 工具契约

工具名：

- `GetStockChipDistribution`

默认定位：

- 面向单股票分析，但保留多股票并行能力，风格与现有 K 线工具一致

### 6.1 输入参数

- `stockCode`
  - 类型：`string`
  - 必填
  - 股票代码，格式与 `GetEastMoneyKLine` 一致，如 `600519.SH`、`000001.SZ`
- `stockCodes`
  - 类型：`array`
  - 可选
  - 多只股票代码列表，与 `stockCode` 合并去重
- `days`
  - 类型：`integer`
  - 可选
  - 样本天数，默认 `240`
- `adjustFlag`
  - 类型：`string`
  - 可选
  - 复权方式，默认 `qfq`
  - 仅支持空值、`qfq`、`hfq`
- `accuracyFactor`
  - 类型：`integer`
  - 可选
  - 价格桶精度，默认 `150`
  - 用于控制价格离散化粒度

### 6.2 输出内容

每只股票默认返回以下内容：

- 最新日期
- 获利比例
- 平均成本
- `90%成本区间`
- `90%集中度`
- `70%成本区间`
- `70%集中度`
- 价格分布明细表

明细表字段：

- `价格`
- `筹码权重(%)`

输出顺序：

- 先摘要
- 再明细表
- 多股票时按输入顺序逐段输出

### 6.3 范围约束

- v1 只支持日 K 数据
- 若调用时未显式指定 `days`，默认使用最近 `240` 个交易日
- 若样本不足，仍可计算，但需要在结果中使用实际数据条数
- 若 K 线数据为空、股票代码无效或关键字段无法解析，返回明确错误提示

## 7. 计算逻辑

### 7.1 输入字段

计算器使用以下字段：

- `Day`
- `Open`
- `Close`
- `High`
- `Low`
- `TurnoverRate`

说明：

- `Volume`、`Amount`、`Amplitude` 本次不作为核心计算字段，但保留在数据源中，不做额外裁剪
- `TurnoverRate` 来自现有 `KLineData`，其语义为百分比数值，例如 `3.45` 表示 `3.45%`

### 7.2 核心算法口径

v1 按东方财富前端 CYQ 思路移植到 Go，核心过程如下：

1. 维护历史价格桶上的筹码权重
2. 对每个交易日，按 `turnoverRate = min(1, hsl / 100)` 计算当日换手比例
3. 先将历史筹码整体乘以 `1 - turnoverRate`，表示未换手部分继续留存
4. 再将当日新增筹码按 `[low, high]` 价格区间分布到价格桶中
5. 当日分布采用以 `(open + close + high + low) / 4` 为中心的三角分布
6. 全部样本遍历完成后，计算：
   - 获利比例
   - 平均成本
   - `70%` 成本区间与集中度
   - `90%` 成本区间与集中度
   - 完整价格分布序列

### 7.3 统计口径

获利比例：

- 以最新收盘价为基准，统计成本不高于该价格的筹码占比

平均成本：

- 以全部价格桶的价格乘权重求加权平均

`70%` / `90%` 成本区间：

- 从累计权重中求覆盖指定比例筹码的最小连续价格区间

集中度：

- 使用区间相对宽度表示
- 口径为 `(区间上界 - 区间下界) / 区间上界 * 100%`

### 7.4 明确假设

以下假设在当前版本中明确成立：

- 无确切信息证明东方财富网页使用了独立的后端 CYQ 数据源，因此 v1 直接基于传入日 K 数据计算
- 默认复权方式取 `qfq`，用于尽量降低历史价格跳变对成本分布的干扰
- v1 不追求与东方财富网页每个价格桶的数值逐点完全一致，而追求同一算法口径下的可解释和稳定输出

## 8. 错误处理

错误处理遵循项目现有工具习惯，但避免静默失败。

需要覆盖的错误场景：

- 股票代码为空或格式非法
- 东财 K 线请求失败
- 东财返回空数据
- `Open`、`Close`、`High`、`Low`、`TurnoverRate` 无法解析
- `accuracyFactor <= 0`

建议行为：

- 参数错误时，直接返回明确中文错误提示
- 数据请求失败时，返回“未获取到筹码分布所需日 K 数据，请检查股票代码与参数”
- 计算阶段出错时，返回“筹码分布计算失败”并附带简要原因
- 不使用“空表格”掩盖真实失败

## 9. 测试设计

本次按 TDD 实施，最少包含三类测试。

### 9.1 计算器单测

目标：

- 验证 CYQ 结果字段完整且数值范围合理

覆盖点：

- 获利比例在 `0` 到 `100` 之间
- 平均成本落在整体价格区间内
- `70%` 成本区间包含于 `90%` 成本区间
- `70%` / `90%` 集中度非负
- 明细桶数量大于 `0`

### 9.2 工具输出单测

目标：

- 验证 markdown 同时包含摘要和明细表

覆盖点：

- 输出包含“获利比例”“平均成本”“90%成本区间”“70%成本区间”
- 输出包含明细表头“价格”“筹码权重(%)”
- 空数据和错误参数时返回明确提示

### 9.3 多股票顺序单测

目标：

- 验证并行执行后仍按输入顺序输出

覆盖点：

- `stockCode` 与 `stockCodes` 合并去重后结果顺序稳定
- 多只股票输出段落顺序与输入一致

以下条件同时满足，才视为本次设计落地完成：

- AI 可调用 `GetStockChipDistribution`
- 默认返回摘要指标和价格分布明细表
- 单只与多只股票都可用

## 12. 后续实现边界

实现阶段只做以下事情：

- 新增筹码分布计算器
- 新增工具 handler 和 schema

- 补充最小关键测试

以下内容留到后续版本再讨论：

- 提供更多统计口径，例如主峰成本、峰值价格、双峰识别
